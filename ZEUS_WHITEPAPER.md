## Abstract

Zeus is a systems language that compiles to readable, zero-heap, formally-verified C and then to native code. Its differentiator is not raw speed (that is table stakes) but a **proof layer**: a Z3-backed verifier in the compile loop, opt-in oblivious memory, `secret` data tracking, deterministic execution, and machine-readable (`--json`) diagnostics. This combination — which no existing language has all of at once — enables a new model of software trust we call **"the artifact proves itself."** Instead of trusting a vendor, a Zeus binary ships a machine-checkable certificate of exactly what was proven about it, and the consumer sets policy for what they will run. This paper records the research grounding, the core thesis, the genuinely novel features it unlocks, an honesty ledger of claims we refuse to make (and what they would actually cost to make true), and a realistic roadmap.

## 1. Where Zeus actually is today **[REAL]**

A source-to-source compiler: `.zs` → readable C → native binary. 36/36 sample programs build; 17/17 golden tests pass.

- **Language:** i32/u64/f64/bool/str, fixed-size arrays `[T; N]`, structs + field access, functions + recursion, `if/else/else-if`, `while`, `for i in a..b`, `&&`/`||`, unary `-`/`!`, correct operator precedence, lexical scoping, `print`/`println` of typed values, a math stdlib (`min`/`max`/`clamp`/`abs`/`sqrt`/`pow`), comptime constant folding.
- **Speed:** emits `-O2 -march=native` C. Measured: SoA hot loops ~9× faster than naive array-of-structs; arena allocation ~3.4× faster than `malloc`.
- **Security:** `secret` keyword (RAM wipe at scope exit); **opt-in oblivious memory** (constant-time full-scan reads/writes for `secret` arrays — defeats the cache-timing table-lookup leak); **zero-heap enforcement** (no `malloc`/`calloc`/`free` in output — MISRA C:2012 Rule 21.3 by construction).
- **Verification:** `@verify` and `@requires`/`@ensures` contracts; real **Z3** integration that proves properties and returns counterexamples; auto-generated `zeus_safety_report.txt`.
- **Parallelism:** multi-core fork-join `parallel` blocks with correct cross-process reductions.
- **Interop / tooling:** `zeus import <header.h>` → `extern fn` bindings (the "plug into existing C systems" capability); line-numbered diagnostics; `--json` machine-readable diagnostics (AI-repair signal).

## 2. Research grounding (June 2026)

**The security wedge is a respected field — and unoccupied at the general-purpose, ergonomic end.**
Constant-time / side-channel-safe languages are real and prestigious: **FaCT** (constant-time DSL, PLDI'19), **Jasmin** (low-level language with a Coq-verified compiler), **HACL\*** (verified C crypto, shipped in Firefox/Linux). 2025 work extends this to *speculative* constant-time (Spectre-safe). All of these are research-grade, crypto-only, and hard to use. **No one offers constant-time + verification in a general-purpose language with first-class C interop that an AI can write fluently.** That is Zeus's opening.

**AI-native languages are a live 2026 frontier.** Vercel Labs shipped **Zero**, a systems language built so AI agents can read, repair, and ship native programs (<10 KiB binaries, JSON diagnostics). The research framing of an ideal LLM-native language: *"a rich IR no human would want to write, paired with a human-facing projection, with formal verification at every step."* The missing ingredient that makes AI-written code trustworthy is **verification as the gate** — the half Zeus already has.

**Proof-Carrying Code (PCC)** is sound, old research (Necula, 1997): ship code together with a machine-checkable proof of a safety policy; the consumer checks the proof before running. It has never been productized as a practical, signed, policy-enforced gate for general software. Zeus can, because Zeus already produces the proof facts.

**Indistinguishability Obfuscation (iO)** exists only on paper (first well-founded construction: Jain–Lin–Sahai, 2020–21) and is astronomically impractical. It is **not purchasable at any price** — pursuing it is a multi-year cryptography research bet, not a product decision.

## 3. The thesis: *the artifact proves itself*

Today you trust software because you trust the vendor. **Zeus inverts this:** a binary carries a machine-checkable certificate of exactly what was proven about it (zero-heap, contracts proven, constant-time, bounded stack/time, no secret leakage), and the *consumer* sets the policy for what they will run. Not "trust me" — "here is the proof; your loader decides."

This reframes Zeus from "a fast secure language" to **"the substrate where code, AI, and humans cooperate through proof."** Speed and zero-heap are table stakes; the **proof layer is the moat** — the one thing the FaCT/Jasmin/HACL crowd cannot productize (too academic) and the Rust/Zig/Vercel-Zero crowd cannot add (no prover in the loop, and a heap that makes worst-case-time and non-leakage analysis undecidable).

## 4. Novel pillars unlocked by the thesis

Each is honest about prior art; the novelty is the *combination + productization* that only Zeus's five-piece foundation enables.

### 4.1 Self-certifying binaries + a policy gate **[REAL]**
Promote `zeus_safety_report.txt` into a signed, machine-checkable **proof certificate** carried with the binary, and add `zeus run --require constant-time,zero-heap` (also a CI gate / app-store policy) that **refuses to execute anything whose certificate doesn't cover what you demand.** *Prior art:* PCC (1997). *New:* shipping it as a runtime/CI policy gate for general software. *Why only Zeus:* it already emits the facts and has a prover.

### 4.2 AI-edit equivalence proofs **[NEXT / RESEARCH]**
Because Zeus is AI-authored *and* verified, make the unit of change a **proven-equivalent transformation**: the AI proposes an edit; Zeus proves (via Z3) the new function is behavior-equivalent to the old, or reports exactly which contract changed. *Prior art:* translation validation (e.g. Alive for LLVM). *New:* an **AI pair-programmer whose diffs are provably behavior-preserving** — the literal realization of "AI writes it, the prover lets a human trust it without reading the IR." This is the most un-built idea here.

### 4.3 Resource bounds as provable types **[REAL seed]**
`@wcet(500us)`, `@stack(4KB)`, `@energy(2mJ)` as contracts the compiler **statically proves and refuses to compile if it cannot bound.** WCET is undecidable in general — but Zeus's restricted, zero-heap, bounded-loop language makes it *decidable*, which is exactly why no general language ships this. Killer feature for automotive / aerospace / space, where teams pay heavily for external WCET tools today.

### 4.4 Proven non-leakage (finish the `secret` keyword) **[REAL seed: constant-time leg]**
Turn `secret` into a real information-flow guarantee: prove that no secret value flows into any public output, branch, memory address, or timing — and certify it. Combined with constant-time analysis, the claim becomes **"this function provably cannot leak the key by any observable channel,"** emitted as readable C with a proof. *Prior art:* non-interference / IFC (Jif, FlowCaml). *New:* a general-purpose, ergonomic, C-emitting, Z3-backed, *certified* version.

### 4.5 Bonus — quarantined / capability-typed FFI **[NEXT]**
When Zeus imports legacy C, attach an enforced capability contract (may it allocate? touch the network? block? exceed X µs?) and refuse to let "pure" Zeus call effectful C without declaring it. *Prior art:* effect systems (Koka). *New framing:* **"legacy C is guilty until proven safe; Zeus quarantines it"** — makes the interop story *safe*, not merely possible.

---

### 4.6 Provably Deterministic Computation — the unifying primitive **[RESEARCH → seed REAL]**
The "missing puzzle piece" that four hot domains each hack around separately: **AI-written code** needs reproducibility to be trustable; **confidential computing/crypto** needs constant-time; **real-time/automotive/aerospace/finance** need bounded WCET; **distributed consensus/blockchains** need byte-identical determinism. No language offers all three as one *proven, typed* property — WCET tools, constant-time DSLs (FaCT/Jasmin), and deterministic-execution research exist only separately and are unusable together. Zeus can unify them because its foundation forces the preconditions: zero-heap kills allocation nondeterminism, fork-join kills thread races, ZIR gives the dataflow, the taint pass gives the machinery, and Z3 discharges the obligations. **Target primitive:** a `@deterministic`/`@chrono` region the compiler proves is *reproducible + time-bounded + timing-leak-free* and certifies. *Rust cannot follow — its heap makes all three undecidable.*
**[REAL seed]** ZIR now computes a per-function **trust profile `{leak-free, reproducible}`**: it proves reproducibility by showing no nondeterministic source (`rand`/`time`/`clock`/IO/...) influences a function, and flags leak sinks. Next bricks: WCET bound (decidable on the zero-heap/bounded-loop subset) and constant-time, completing the triple, then emit it in the certificate (§4.1).

## 5. Honesty ledger — claims we do NOT make, and the cost to make them real

We deliberately drop three grand claims, because they are checkable and would cost credibility. For each, the honest, fundable version and rough order-of-magnitude cost.

| Grand claim **[DROPPED]** | Can money buy it? | Honest version we *can* fund **[NEXT/NORTH STAR]** | Rough cost |
|---|---|---|---|
| "Replaces the OS / bare metal / bypasses the kernel" | The *data path*, yes (DPDK/SPDK/io_uring style, on top of an OS via VFIO). A real unikernel only for *narrow* hardware (the driver problem is the moat). Full OS replacement: effectively infinite. | Kernel-bypass I/O for the hot path; honest "talks to hardware directly" | ~$0.5–2M, 1–2 yr, 2–3 systems engineers |
| "iO / unbreakable / can't be reverse-engineered" | **No.** iO is a research frontier (impractical at any budget); "unbreakable" is physically impossible. | Hardware enclaves (TDX/SEV-SNP/CCA) + commercial anti-tamper + the constant-time/oblivious work Zeus already has | ~$0.3–1M, ~1 yr |
| "Self-learning AI baked into every binary" | Cheap to *build*, ruinous to *ship* — it destroys determinism, verification, MISRA cert, and adds a data-poisoning attack surface. | Deterministic, fixed-weight, constant-time **edge inference** (retrained & recertified offline) — keeps every pillar | ~$0.3–1M, ~1 yr |

**Key insight:** the honest versions cost a fraction of the grand versions, are buildable, and are what buyers in the wedge actually want. The cheapest, highest-credibility path funds all three honest tracks (~$1–4M, 18–30 months, ~4–6 specialized engineers) and lets the marketing be the *true* statement — which is already stronger than the hype.

**Adoption-critical (do first):** real type checker + parser error recovery; bidirectional C FFI (let C call Zeus too); modules/imports + a package manifest; static proof of `@requires`/`@ensures` + `@invariant`; `zeus verify --constant-time`; sum types + pattern matching + `Result`; LSP/formatter/tutorial.

**Thesis-defining (the moat):** §4.1 self-certifying binaries + `--require` gate; §4.3 provable `@stack`/`@wcet`; §4.4 proven non-leakage; §4.2 AI-edit equivalence proofs.

**Smallest build that makes the thesis visible:** emit a signed certificate from the existing safety pass + prove a `@stack`/`@wcet` bound from the (already bounded) loop structure + a `zeus run --require ...` gate. A working "self-certifying binary" demo that *no one else can show.*

## 7.5 Architecture (ADR-001) — the build we are growing toward

**Decision: keep the prototype, evolve it — do not rewrite.** The current AST→C path is an asset; we layer a real IR underneath it.

**Implementation language:** Rust (keep). Hand-written recursive-descent parser (keep — best errors, full control).

**The one structural change that fixes speed, security, and adaptability at once:** insert a **typed, SSA-based mid-level IR — ZIR — between the AST and codegen.** Dataflow (def-use) lives here, so: security becomes real analysis (taint / constant-time / non-leakage), optimization runs here, and the **proof attaches to ZIR** so we *prove once and certify every backend*. **[ZIR Phase 1 is now REAL]** — `zir.rs` lowers the AST to typed SSA and runs the `secret`-taint / non-leakage pass alongside the existing pipeline.

**Backends off the one IR (the adaptability moat):**
- **Cranelift** (pure-Rust) for fast debug builds — no C/LLVM dependency, sub-second native compiles. *[NEXT]*
- **C** (keep, default) for portability + legacy interop + auditability — "runs anywhere a C compiler runs." *[REAL]*
- **LLVM** (feature-gated) for release-grade optimization + every target (ARM/RISC-V/WASM). *[NEXT]*
- **WASM** for the browser/edge playground (adoption). *[NEXT]*

**Prover:** Z3 behind an oracle trait; proofs content-addressed/cached. *[REAL seed: `.zeus_verify_cache`]*
**Incremental core:** a salsa-style query engine (memoized, demand-driven) → sub-second rebuilds, an LSP almost for free, and a fast AI edit→prove loop. *[NEXT]*
**Memory model:** formalize zero-heap/arena/regions into the type system with an IR-level ownership/lifetime check — this is what makes "no use-after-free", WCET, and non-leakage *decidable*. *[RESEARCH/NEXT]*

**Migration phases:** (1) insert ZIR + move type-checking & verification onto it [in progress]; (2) query/incremental + LSP; (3) Cranelift + WASM; (4) regions/ownership + constant-time/non-leakage passes + certificate emission; (5) LLVM + written spec + conformance suite + package manager.

**Why it wins both audiences:** devs get fast builds + great errors + a playground; big tech gets the certificate/policy gate (supply-chain trust), C interop, reproducible builds, and MISRA/ISO artifacts. The throughline: **ZIR + proof-at-the-IR + pluggable backends makes speed, security, and adaptability the same mechanism instead of three competing hacks.**
